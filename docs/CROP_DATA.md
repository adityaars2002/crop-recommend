# Crop Data Documentation

## Overview
As part of Phase 4 (Django Integration), a database-backed `Crop` model was introduced to store structural information about each crop class recognized by the Machine Learning recommendation model.

## Data Source
The initial dataset defining the 22 crops (e.g., rice, maize, chickpea, apple, etc.) was generated by synthesizing general botanical and agronomic knowledge corresponding to the labels found in the original **Crop Recommendation Dataset**.

**Important Constraints Applied:**
- No arbitrary values were invented for highly specific numeric fields if they couldn't be generalized. Instead, fields like `min_temperature` or `max_temperature` were left `null` where a broad, safe range couldn't be easily standardized for the entire species.
- The `min_ph` and `max_ph` ranges reflect standard agricultural guidelines (e.g., rice preferring slightly acidic to neutral soil, 5.0 - 6.5).
- Qualitative fields like `water_requirement` and `soil_type` contain general categorical data.

## Seeding Mechanism
The baseline crop data is stored in a JSON file at:
`data/crops/crops.json`

This file is loaded into the Django database using a custom management command:
```bash
python manage.py seed_crops
```

This ensures that the API will always resolve the string outputs of the ML model (e.g., "rice") to a fully populated, queryable database entity with a unique ID, allowing the frontend to display rich information alongside the recommendation score.

## Future Improvements
For a production environment, the generalized data in `crops.json` should be verified by a certified agronomist or replaced with data sourced from local agricultural extension services to ensure region-specific accuracy.
